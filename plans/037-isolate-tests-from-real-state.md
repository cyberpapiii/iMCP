## Why this matters

The app test bundle is injected into the real `iMCP.app` binary (`TEST_HOST`),
and that host boots exactly like the installed app: it opens the production
paired-client store, replays the stored iCloud session against Apple, and
starts a Bonjour-advertised listener named `iMCP`. Every `Scripts/test.sh` run
therefore spends a real Apple session replay and puts a second, handler-less
"iMCP" server on the machine. Separately, `Scripts/test.sh` freezes the
always-on watchdog and kills the app *before* it arms the trap that restores
them, `Scripts/ship.sh` carries a second copy of that logic with the same bug
and keeps the app dead through the whole CI wait, and `test.sh` exits 0 when
its flags select no suite. After this plan: the test host is inert, there is
one implementation of "stop the app, test, restore", an interrupt always
restores the app, an empty selection fails, and three pieces of test-only
surface are gone from production code.

### `Scripts/test.sh` (113 lines)

- `:32-46` argument parsing. `--app-only` sets `RUN_CLI="0"`; `--cli-only` sets
  `RUN_APP="0"`; `--only SPEC` appends to `only_specs` and sets `RUN_CLI="0"`.
  So `--app-only --cli-only` and `--cli-only --only X` leave both at `"0"`,
  every later block is skipped, and the script exits 0 having run nothing.
- `--only SPEC` is passed as `-only-testing:SPEC` to the `iMCP` scheme
  (`:106-112`), so SPEC must start with the test target:
  `iMCPTests/<Class>` or `iMCPTests/<Class>/<method>`.
- `:53-64` defines `restore_app`. `:66-77`:

  ```bash
  if [[ "${RUN_APP}" == "1" ]]; then
    while IFS= read -r helper_pid; do
      [[ -n "${helper_pid}" ]] || continue
      always_on_pids+=("${helper_pid}")
      kill -STOP "${helper_pid}"
    done < <(pgrep -x iMCPAlwaysOn || true)

    if pgrep -f "/Applications/iMCP.app/Contents/MacOS/iMCP" >/dev/null 2>&1; then
      app_was_running="1"
      pkill -f "/Applications/iMCP.app/Contents/MacOS/iMCP" || true
    fi
    trap restore_app EXIT
  ```

  The trap is armed after the SIGSTOP and the `pkill`. An interrupt in between
  leaves the app dead under a frozen watchdog. `restore_app` is safe to run
  when nothing was stopped (empty array, `app_was_running="0"`), so it can be
  armed unconditionally and first.

### `Scripts/ship.sh` (336 lines)

- `:151` `swift format lint --strict --recursive .` — keep.
- `:152-153` build-for-testing and the CLI suite.
- `:155-190` a second copy of the stop/restore logic, trap armed at `:179`

- `:192-251` `run_bounded_app_tests`: runs `xcodebuild -quiet test -scheme iMCP`
  directly with a 180 s kill timer, and turns a timeout (124) or a
  LaunchServices launch error (125) into a warning and **continues to commit
  and push**.
- `:321` `app_was_running="0"` after `Scripts/install-local.sh verify`, so the

- `Scripts/install-local.sh:195-200` (`open_app`) kills and reopens the app

**Decision on what is preserved** (so you do not have to judge): the 180 s
timeout and the 124/125 "warn and continue" branches are **deleted, not moved
into `test.sh`**. They were written when the app suite took 65 s and collided
with the installed app; the suite now takes about 5 s and `test.sh` stops the
app first. Both branches convert a local test failure into a push. After this
plan a hung or blocked local run fails the ship before the commit, which is the
correct outcome; CI remains the merge gate either way.
